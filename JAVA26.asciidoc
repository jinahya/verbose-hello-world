:lang: ko

== Scope and Baseline

이 문서는 Java 25 기반 예제를 Java 26을 거쳐 Java 27로 옮길 때의 변경 사항과 추가할 학습 예제를 정리한다.
확인일은 2026-11-12이며, Java 26은 2026-03-17에 정식 출시되었다.
출시 기능 목록은 https://openjdk.org/projects/jdk/26/[OpenJDK JDK 26]을 기준으로 한다.
Java 27에서 이어지는 변경 사항은 link:JAVA27.asciidoc[Java 27]을 참고한다.

현재 작업 트리의 `pom.xml`, `.java-version`, `.github/workflows/maven.yml`은 이미 Java 27을 선택한다.
따라서 아래 내용은 Java 26으로 빌드 설정을 되돌리는 작업 지시가 아니라, Java 25 이후의 차이를 설명하는 문서이다.
이 문서의 추가 제안은 구현 완료를 뜻하지 않는다.

== Release Changes

[cols="1,3,4",options="header"]
|===
|JEP |Feature / Status |Change from Java 25

|https://openjdk.org/jeps/500[500]
|Prepare to Make Final Mean Final
|Deep reflection으로 `final` 필드를 변경하는 동작에 기본적으로 경고한다. 향후 제한 강화에 대비하는 변경이다.

|https://openjdk.org/jeps/504[504]
|Remove the Applet API
|제거 예정으로 deprecated되어 있던 Applet API를 제거한다.

|https://openjdk.org/jeps/516[516]
|Ahead-of-Time Object Caching with Any GC
|AOT 객체 캐시를 ZGC를 포함한 모든 GC에서 사용할 수 있도록 확장한다.

|https://openjdk.org/jeps/517[517]
|HTTP/3 for the HTTP Client API
|`java.net.http`에 HTTP/3 지원을 추가한다. 기본 프로토콜은 HTTP/2이며 HTTP/3는 명시적으로 선택한다.

|https://openjdk.org/jeps/522[522]
|G1 GC: Improve Throughput by Reducing Synchronization
|애플리케이션 스레드와 GC 스레드 사이의 동기화 비용을 줄인다. 애플리케이션 API 변경은 없다.

|https://openjdk.org/jeps/524[524]
|PEM Encodings of Cryptographic Objects — Second Preview
|`PEMRecord`를 `PEM`으로 변경하고 키 쌍 등의 암호화·복호화 지원을 조정한다.

|https://openjdk.org/jeps/525[525]
|Structured Concurrency — Sixth Preview
|Joiner의 결과, 이름, timeout 처리와 scope 설정 함수의 타입을 변경한다.

|https://openjdk.org/jeps/526[526]
|Lazy Constants — Second Preview
|Java 25의 `StableValue`를 `LazyConstant`로 바꾸고 고수준 지연 초기화 중심으로 API를 개편한다.

|https://openjdk.org/jeps/529[529]
|Vector API — Eleventh Incubator
|Incubator 상태를 유지한다. JEP는 실질적인 API 변경 없이 재인큐베이션한다고 설명한다.

|https://openjdk.org/jeps/530[530]
|Primitive Types in Patterns, instanceof, and switch — Fourth Preview
|Unconditional exactness 정의와 `switch`의 dominance 검사를 강화한다. 일부 기존 preview 소스는 컴파일되지 않을 수 있다.
|===

위 목록은 출시 JEP 목록이다. 모든 API 추가, 버그 수정, 보안 기본값 변경을 열거한 목록은 아니다.
세부 호환성 검토에는 https://www.oracle.com/java/technologies/javase/26all-relnotes.html[JDK 26 Release Notes]도 함께 사용한다.

== Existing Code to Revisit

=== Structured Concurrency

관련 구현은 `01-verbose-hello-world-api/src/main/java/com/github/jinahya/hello/api/StructuredConcurrencyHelloWorld.java`이며,
동일 패키지의 `StructuredConcurrencyHelloWorld_ApplyAsync_Mapper_*` 테스트와
`_java_nio_channels`, `_java_nio_file`의 구조적 동시성 테스트로 이어진다.

Java 25 → 26의 주요 차이는 다음과 같다.

* `Joiner.allSuccessfulOrThrow()`의 결과가 subtask의 stream에서 결과의 list로 바뀐다.
* `anySuccessfulResultOrThrow()`가 `anySuccessfulOrThrow()`로 바뀐다.
* `Joiner.onTimeout()`이 추가된다.
* Joiner와 설정 함수를 받는 `open`은 `Function` 대신 `UnaryOperator`를 받는다.

현재 구현은 이미 `UnaryOperator<StructuredTaskScope.Configuration>`와 `Joiner.allUntil(...)`을 사용한다.
이 파일에 사용하지 않는 이전 메서드명을 기계적으로 치환할 필요는 없다.
Java 27에서는 다시 API 변경이 있으므로 최종 대상 JDK의 시그니처까지 확인해야 한다.

추가할 예제는 정상 완료뿐 아니라 mapper 실패, timeout, interruption, scope 종료 시 subtask 정리를 다루어야 한다.
`CompletionStage`의 취소와 scope의 취소가 자동으로 같은 동작이 되는 것으로 설명하지 않는다.

=== HTTP Client

`01-verbose-hello-world-api/src/test/java/com/github/jinahya/hello/api/_java_net_http/`에는
`HelloWorld.method(HttpRequest.Builder, String)`의 테스트가 있다.
이 builder 검증과 실제 HTTP/3 통신 검증은 별도의 학습 주제이다.

추가할 통합 예제에서는 `HttpClient.Version.HTTP_3`를 선택하고, 제어 가능한 HTTP/3 서버에
`hello, world` 요청 본문을 보내 응답 본문과 `HttpResponse.version()`을 검증한다.
HTTP/3 요청 설정만으로 협상 결과를 단정하지 않고 fallback도 별도로 확인한다.
HTTP/3 서버와 QUIC/UDP 통신 조건이 필요한 테스트는 일반 단위 테스트와 분리한다.
JEP 517은 HTTP/3 서버 구현이나 범용 QUIC API를 제공하지 않는다.

=== Reflection and Dependencies

Mockito, Lombok, AspectJ, DI/CDI 구현은 부모 `pom.xml`과 각 모듈의 profile에 걸쳐 사용된다.
JEP 500의 영향은 실제 `final` 필드 변경 경고와 해당 라이브러리의 동작을 확인해 판단한다.
모든 `setAccessible(true)` 호출이 곧 `final` 필드 변경인 것은 아니다.

추가할 작은 reflection 예제는 생성자에서 초기화한 인스턴스 `final` 필드를 변경하고,
별도 JVM에서 기본 경고 동작과 `--illegal-final-field-mutation=deny` 동작을 비교한다.
필요한 경우의 `--enable-final-field-mutation`과 패키지 접근을 위한 `--add-opens`는 서로 다른 설정이다.
경고를 없애기 위해 프로젝트 전체에 허용 옵션을 먼저 추가하지 않는다.
구체적인 옵션 의미는 https://openjdk.org/jeps/500[JEP 500]을 따른다.

Applet 제거는 오래된 참조와 의존성을 점검할 항목이다.
API 모듈의 `requires java.desktop`을 Applet 제거만을 근거로 삭제하지 않는다.
`java.desktop` 자체가 제거된 것은 아니다.

|===

|실제 요청 본문 전송, 응답 프로토콜 확인, fallback, 비동기 실패를 검증하는 선택적 통합 예제.

|`hello.miscellaneous` — Lazy Constants
|Eager `final`, 직접 만든 lazy 초기화, `LazyConstant`를 비교한다. 여러 스레드의 접근, 초기화 실패 후 동작, `null` 거부를 확인한다.

|P1
|`hello.miscellaneous` — Primitive Patterns
|정확히 표현 가능한 숫자와 손실이 생기는 변환, 경계값, `NaN`/infinity, 강화된 dominance 규칙을 다룬다. 컴파일 오류 예제는 설명용으로 분리한다.

|P2
|`hello.miscellaneous` — PEM
|키 및 인증서의 PEM 왕복 변환, 잘못된 입력, 암호화된 개인키의 잘못된 비밀번호를 검증한다. 기존 `_java_security`, `_javax_crypto` 예제에 연결한다.

|P2
|별도 실행 예제 — Reflection
|JEP 500 경고와 거부를 별도 프로세스에서 확인한다. 해당 테스트가 메인 테스트 JVM의 상태에 의존하지 않게 한다.

|P3
|선택적 성능 예제 — AOT / G1 / Vector
|동일한 workload의 시작 시간과 처리량을 비교한다. 짧은 greeting 한 번의 실행만으로 성능 향상을 주장하지 않는다.
|===

Lazy Constants 예제에는 Java 25의 `StableValue`에서 사라진 `orElseSet`, `setOrThrow`, `trySet`을 그대로 옮기지 않는다.
Java 26은 계산 함수를 받는 factory를 중심으로 구성하며, 지연 list/map factory는 `List`와 `Map`에 위치한다.
계산 결과로 `null`을 허용하지 않는다. Java 27의 추가 차이는 다음 문서에서 설명한다.

기존 `hello.miscellaneous._Javax_Crypto_KDF_Test`는 이미 HKDF를 다룬다.
기존 Java 25 기능과 새 PEM 학습 예제를 구분하고, KDF 자체를 Java 26 신규 기능으로 소개하지 않는다.

Vector API 예제는 `jdk.incubator.vector` 모듈이 필요하다.
컴파일과 실행에 필요한 `--add-modules jdk.incubator.vector` 및 모듈 경로를 선택적 예제에 한정한다.
Preview 활성화만으로 incubator 모듈이 추가되는 것은 아니다.

== Build and Verification Notes

Preview 클래스는 사용한 JDK 버전에 맞춰 다시 컴파일하고 해당 버전으로 실행해야 한다.
Java 25 preview 바이너리를 Java 26이나 Java 27에서 `--enable-preview`만 추가해 재사용할 수 있다고 안내하지 않는다.
Java 26 preview를 직접 비교하려면 별도 checkout과 JDK 26을 사용하여 compiler release, Enforcer 범위,
Maven 실행 JDK 및 테스트 JVM을 모두 맞춘다. 현재 Java 27 설정에서 compiler 숫자 하나만 바꾸는 방식은 피한다.

현재 변경 제안의 검증 순서는 다음과 같다.

. 최종 대상인 JDK 27에서 전체 모듈을 다시 컴파일하고 기존 테스트를 실행한다.
. 새 API 예제를 추가한 뒤 실제 동작을 검증한다. HTTP/3처럼 외부 조건이 있는 예제는 선택적 통합 테스트로 실행한다.
. DI/CDI profile과 생성된 실행 JAR의 동작까지 확인한다.
. 성능 관련 설명은 측정 환경과 반복 횟수를 기록한 별도 실험으로 검증한다.

이 문서를 작성하는 작업에서는 Java 소스나 빌드 설정을 변경하지 않았으며 위 Java 검증을 수행한 것으로 간주하지 않는다.
