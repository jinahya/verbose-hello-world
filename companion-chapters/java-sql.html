java.sql

java.sql 은 자바 프로그램이 관계형 데이터베이스에 접근하는 JDBC (Java Database Connectivity) API 를 담은 패키지이다.[1] 자바 프로그램은 이 패키지의 인터페이스로 SQL 문에 값을 넘기고, 결과 집합의 행을 고치고, 큰 이진 / 문자 값을 다룬다. 이 인터페이스들의 구현은 JDK 가 아니라 각 데이터베이스의 JDBC 드라이버가 제공한다.

이 절에서는 hello, world 바이트들을 다음 여섯 가지 대상에 기록하는 메서드들을 다룬다.

대상 기록하는 곳 메서드 이름

PreparedStatement

번호로 지정한 SQL 매개변수

set…​(preparedStatement, parameterIndex)

CallableStatement

이름으로 지정한 저장 프로시저 매개변수

set…​(callableStatement, parameterName)

ResultSet

번호나 이름으로 지정한 현재 행의 열

update…​(resultSet, columnIndex) / update…​(resultSet, columnLabel)

Blob

BLOB 값의 지정한 위치

set…​(blob, pos)

Clob

CLOB 값의 지정한 위치

set…​(clob, pos)

SQLOutput

사용자 정의 SQL 형의 출력 스트림

write…​(output)

JdbcHelloWorld

이 메서드들은 HelloWorld 의 소스 파일이 아니라 패키지 전용 (package-private) 인터페이스 JdbcHelloWorld 에 선언되어 있다. 메서드가 오십 개가 넘어 HelloWorld.java 에서 따로 떼어 낸 것이다. HelloWorld 는 JdbcHelloWorld 를 확장하는 유일한 인터페이스이므로, 이 절의 메서드는 모두 HelloWorld 의 공개 메서드이다. 호출자는 JdbcHelloWorld 라는 이름을 볼 일이 없고, HelloWorld 의 값에 대고 바로 setBytes(preparedStatement, 1) 처럼 호출한다.

HelloWorld
public interface HelloWorld extends JdbcHelloWorld {

JdbcHelloWorld 는 추상 메서드 set(byte[], int) 하나를 선언한다. HelloWorld 가 선언하는 set(byte[], int) 와 이름과 형이 같으므로 두 선언은 같은 메서드 하나가 되고, HelloWorld 는 여전히 추상 메서드가 하나뿐인 함수형 인터페이스로 남는다.

JdbcHelloWorld
import static com.github.jinahya.hello.api.JdbcHelloWorldUtils.*; (1)

interface JdbcHelloWorld {

    byte[] set(byte[] array, int index);                          (2)

    ...
}
1 JdbcHelloWorldUtils 의 정적 메서드 array(…​) 와 string(…​) 을 이름만으로 부를 수 있게 한다.
2 이 인터페이스의 모든 기본 메서드가 기대는 유일한 메서드이다.

JdbcHelloWorld 의 기본 메서드는 array(this) 나 string(this) 로 값을 만든 뒤, 그 값을 JDBC 메서드 하나에 넘기고, 받은 대상을 그대로 반환한다. 두 메서드는 같은 패키지의 클래스 JdbcHelloWorldUtils 에 있고, 바이트 수는 JdbcHelloWorldConstants 의 상수에서 가져온다. 두 클래스 모두 패키지 전용이므로 HelloWorld 의 구현체도 호출자도 쓸 수 없다.

JdbcHelloWorldConstants

hello, world 의 바이트 수 12 를 상수 BYTES 로 둔다.

JdbcHelloWorldConstants

    static final int BYTES = 12;

    private JdbcHelloWorldConstants() {
        throw new AssertionError("instantiation is not allowed");
    }
}

JdbcHelloWorldUtils

JdbcHelloWorld 의 값 하나를 받아 hello, world 를 바이트 배열이나 문자열로 만들어 주는 정적 메서드 두 개를 둔다.

JdbcHelloWorldUtils
final class JdbcHelloWorldUtils {

    static byte[] array(final JdbcHelloWorld service) {
        Objects.requireNonNull(service, "service is null");
        final var array = new byte[JdbcHelloWorldConstants.BYTES];    (1)
        service.set(array, 0);                                        (2)
        return array;
    }

    static String string(final JdbcHelloWorld service) {
        Objects.requireNonNull(service, "service is null");
        return new String(array(service), StandardCharsets.US_ASCII); (3)
    }

    private JdbcHelloWorldUtils() {
        throw new AssertionError("instantiation is not allowed");
    }
}
1 길이가 12 인 새 배열을 만든다.
2 그 배열을 service.set(array, 0) 으로 채워 반환한다. 바이트 값을 받는 메서드들이 쓴다.
3 array(service) 가 반환한 배열을 US-ASCII 로 디코딩한 문자열을 반환한다. 문자열이나 문자 스트림을 받는 메서드들이 쓴다.

시험 계층

JdbcHelloWorld 의 메서드들은 HelloWorldTest / HelloWorldTestUtils 와 같은 모양의 시험 계층을 따로 가진다.

시험 클래스는 모두 추상 클래스 JdbcHelloWorld__Test 를 확장한다. 이 클래스는 JdbcHelloWorld 의 spy 를 service() 로 내어 준다.

JdbcHelloWorld__Test

@Slf4j
abstract class JdbcHelloWorld__Test {

    @Spy
    @Accessors(fluent = true)
    @Getter(AccessLevel.PROTECTED)
    private JdbcHelloWorld service;
}

JdbcHelloWorld__TestUtils 는 service() 의 set(byte[], int) 를 스텁하고 검증하는 정적 메서드를 모아 둔 클래스이다.

메서드 하는 일

set_array_index_returns_the_array(service)

set(array, index) 가 받은 배열을 그대로 반환하도록 스텁한다.

set_array_index_sets_random_bytes(service)

set(array, index) 가 index 부터 12 바이트를 임의의 값으로 채워 반환하도록 스텁한다.

set_array_index_sets_hello_world_bytes(service)

set(array, index) 가 index 부터 12 바이트를 실제 hello, world 바이트로 채워 반환하도록 스텁한다.

set_array12_index0_invoked_once(service)

set(array, 0) 이 길이가 12 인 배열로 딱 한 번 호출되었음을 검증하고, 포착한 배열을 반환한다.

    requireMock(service);
    final var captor = ArgumentCaptor.forClass(byte[].class);
    verify(service, times(1)).set(captor.capture(), eq(0));    (1)
    final var array = captor.getValue();

1 set(byte[], int) 가 두 번째 인자 0 으로 딱 한 번 호출되었는지 검증하며 첫 번째 인자를 포착한다.
2 포착한 배열의 길이가 12 인지 확인한다.

메서드마다 시험 클래스가 두 개씩 있다. JdbcHelloWorld_<동작>_<대상>_Test 는 JDBC 객체를 모의 객체로 두고, 메서드가 인자를 검증하는지, 알맞은 JDBC 메서드에 알맞은 값을 넘기는지, 받은 대상을 그대로 반환하는지 확인한다. 다른 하나는 메서드 자신을 스텁한 뒤 실제 JDBC 드라이버의 객체로 값을 기록하고 다시 읽어 본다. SQLOutput 을 받는 메서드에는 앞의 시험 클래스만 있다.

시험에 쓰는 데이터베이스

실제 드라이버로 기록하는 시험은 두 가지 내장 데이터베이스를 쓴다. 둘 다 시험 범위 (test scope) 의존성이며, 별도의 서버 없이 메모리 안에 데이터베이스를 만든다.

데이터베이스 드라이버 연결 URL 의 예

H2

com.h2database:h2

jdbc:h2:mem:<이름>;DB_CLOSE_DELAY=-1

SQLite

org.xerial:sqlite-jdbc

jdbc:sqlite::memory:

드라이버가 구현하지 않은 기능을 쓰는 시험은 @Disabled 로 꺼 두고, 그 이유를 어노테이션 값에 적었다.

  • SQLite 드라이버는 저장 프로시저를 지원하지 않고, 갱신할 수 없는 (CONCUR_READ_ONLY) 결과 집합만 만들며, Connection.createBlob() / createClob() 을 구현하지 않는다.

  • H2 드라이버는 CallableStatement 의 매개변수 이름을 해석하지 않는다.

그래서 CallableStatement 를 받는 메서드는 두 드라이버 어느 쪽으로도 실제로 기록해 보지 못하고, 모의 객체로 확인하는 시험만 실행된다.

Java 26 부터 Blob 과 Clob 은 AutoCloseable 을 확장하고, 기본 close() 메서드를 가진다. 기본 구현은 free() 를 호출한다. 이제 free() 를 직접 부르는 대신 try-with-resources 로 자원을 돌려줄 수 있다.[2]

java.sql.PreparedStatement

java.sql.PreparedStatement 는 미리 컴파일한 SQL 문을 나타내는 인터페이스이다.[3] SQL 문의 ? 가 매개변수 하나를 나타내며, 호출자는 setXxx(parameterIndex, value) 형식의 메서드로 각 매개변수에 값을 넣은 뒤 executeUpdate() 나 executeQuery() 로 실행한다. parameterIndex 는 1 부터 센다.

JdbcHelloWorld 의 메서드들은 PreparedStatement 를 확장한 형(T)의 값과 매개변수 번호를 받아서, hello, world 를 그 매개변수의 값으로 넣은 후, 명시된 PreparedStatement 를 그대로 반환한다. SQL 문을 실행하지는 않는다.

setAsciiStream(PreparedStatement, int)

setAsciiStream(PreparedStatement, int) 는 hello, world 바이트들을 ASCII 스트림으로 지정한 매개변수에 넣는다.[4]

HelloWorld#setAsciiStream(PreparedStatement, int)
<T extends PreparedStatement> T setAsciiStream(T preparedStatement, int parameterIndex)
        throws IOException, SQLException

  • hello, world 바이트들을 주어진 준비된 문의 지정한 매개변수에 ASCII 스트림 값으로 넣는다.

  • T (타입 매개변수): 호출자가 건넨 준비된 문의 구체 타입.

  • preparedStatement (매개변수): 값을 넣을 준비된 문.

  • parameterIndex (매개변수): 매개변수 번호. 첫 번째 매개변수가 1 이다.

  • 반환값: 주어진 preparedStatement.

  • NullPointerException (예외): preparedStatement 가 null 인 경우.

  • IllegalArgumentException (예외): parameterIndex 가 양수가 아닌 경우.

  • IOException (예외): 입출력 오류가 발생한 경우.

  • SQLException (예외): parameterIndex 에 해당하는 매개변수가 없거나, 데이터베이스 접근 오류가 발생했거나, 닫힌 PreparedStatement 에 대해 호출한 경우.

  • 기본 구현: set(new byte[12], 0) 으로 배열을 얻어 ByteArrayInputStream 으로 감싸고, preparedStatement.setAsciiStream(parameterIndex, stream) 를 호출한 뒤, 스트림을 닫고 preparedStatement 를 반환한다.

JdbcHelloWorld#setAsciiStream(preparedStatement, parameterIndex)
default <T extends PreparedStatement> T setAsciiStream(final T preparedStatement,
                                                       final int parameterIndex)
        throws IOException, SQLException {
    Objects.requireNonNull(preparedStatement, "preparedStatement is null");
    if (parameterIndex < 1) {
        throw new IllegalArgumentException("non-positive parameterIndex: " + parameterIndex);
    }
    try (var x = new ByteArrayInputStream(array(this))) {    (1)
        preparedStatement.setAsciiStream(parameterIndex, x); (2)
    }
    return preparedStatement;
}
1 array(this) 로 얻은 배열을 ByteArrayInputStream 으로 감싼다. 이 스트림은 try 블록이 끝날 때 닫힌다.
2 그 스트림을 parameterIndex 번째 매개변수의 값으로 넣는다.

실제 드라이버로 기록하기

실제 드라이버로 확인하는 시험은 먼저 setAsciiStream(PreparedStatement, int) 자신을 스텁한다. 그래서 메서드의 구현이 없어도 실행된다.

setAsciiStream(PreparedStatement, int) 스텁
@BeforeEach
void __() throws IOException, SQLException {
    set_array_index_returns_the_array(service());
    doAnswer(i -> {
        final var statement = i.getArgument(0, PreparedStatement.class);
        final var index = i.getArgument(1, Integer.class);
        statement.setAsciiStream(index, new ByteArrayInputStream(hello_world_byte_array())); (1)
        return statement;
    }).when(service()).<PreparedStatement>setAsciiStream(notNull(), intThat(v -> v >= 1));
}
1 스텁은 hello, world 바이트 배열을 감싼 ByteArrayInputStream 을 받은 매개변수에 직접 넣는다.

H2 에서는 길이가 12 인 VARCHAR 열을 가진 테이블을 만들고, 스텁한 setAsciiStream(statement, 1) 로 INSERT 문의 매개변수를 채워 실행한 뒤, 그 열을 ASCII 스트림으로 다시 읽어 확인한다.

java.sql.CallableStatement 는 저장 프로시저를 호출하는 SQL 문을 나타내는 인터페이스이다.[14] PreparedStatement 를 확장하므로 번호로 매개변수를 지정하는 setXxx(parameterIndex, value) 메서드도 그대로 쓸 수 있다. 여기에 더해 setXxx(parameterName, value) 형식으로 저장 프로시저의 매개변수를 이름으로 지정하는 메서드들을 선언한다.

java.sql.ResultSet

java.sql.ResultSet 은 조회 결과의 행들을 나타내는 인터페이스이다.[25] 커서가 현재 행을 가리키며, next() 를 호출하면 커서가 다음 행으로 옮겨 간다. 열은 번호 (columnIndex) 나 레이블 (columnLabel) 로 지정한다. columnIndex 는 1 부터 센다. 갱신 가능한 결과 집합 (ResultSet.CONCUR_UPDATABLE) 이라면 updateXxx(…​) 메서드로 현재 행의 열 값을 바꾼 뒤, updateRow() 로 그 행을 데이터베이스에 반영한다. 삽입 행 (moveToInsertRow()) 에서 값을 채웠다면 insertRow() 로 새 행을 넣는다.

JdbcHelloWorld 의 메서드들은 ResultSet 을 확장한 형(T)의 값과 열 번호나 열 레이블을 받아서, 현재 행의 그 열 값을 hello, world 로 바꾼 후, 명시된 ResultSet 을 그대로 반환한다. updateXxx(…​) 만 호출하고 updateRow() 나 insertRow() 는 호출하지 않는다. 바꾼 값을 데이터베이스에 반영하는 일은 호출자가 맡는다. 스트림이나 리더를 넘기는 메서드는 그 스트림이나 리더를 닫지 않는다. 메서드가 반환된 뒤에도 드라이버가 읽을 수 있기 때문이다.

실제 드라이버로 확인하는 시험은 H2 와 SQLite 두 가지가 있다. SQLite 로 확인하는 시험은 모두 @Disabled 로 꺼져 있다. SQLite JDBC 드라이버가 읽기 전용 (CONCUR_READ_ONLY) 결과 집합만 지원하기 때문이다.

java.sql.Blob

java.sql.Blob 은 SQL BLOB (binary large object) 값을 나타내는 인터페이스이다.[46] BLOB 은 크기가 큰 이진 값을 담는 SQL 형이다. Blob 의 메서드가 받는 위치 pos 는 1 부터 센다. 첫 번째 바이트의 위치가 1 이며, 0 부터 세는 배열의 인덱스와 다르다.

JdbcHelloWorld 의 메서드들은 Blob 을 확장한 형(T)의 값과 위치를 받아서, hello, world 바이트들을 그 위치부터 기록한 후, 받은 Blob 을 그대로 반환한다. 기록한 Blob 을 테이블의 열에 저장하는 일은 호출자가 한다.

Java 26 부터 Blob 은 AutoCloseable 을 확장하고, 기본 close() 메서드는 free() 를 호출한다.[47] JdbcHelloWorld 의 메서드는 받은 Blob 에 대해 free() 도 close() 도 호출하지 않는다. 실제 드라이버로 확인하는 시험들도 connection.createBlob() 으로 만든 Blob 을 try-with-resources 로 감싸지 않고, free() 나 close() 를 호출하지 않는다.

java.sql.Clob

java.sql.Clob 은 SQL CLOB (character large object) 값을 나타내는 인터페이스이다.[50] CLOB 은 크기가 큰 문자 값을 담는 SQL 형이다. Clob 의 메서드가 받는 위치 pos 는 1 부터 센다. 첫 번째 문자의 위치가 1 이다.

JdbcHelloWorld 의 메서드들은 Clob 을 확장한 형(T)의 값과 위치를 받아서, hello, world 를 그 위치부터 기록한 후, 받은 Clob 을 그대로 반환한다. 기록한 Clob 을 테이블의 열에 저장하는 일은 호출자가 한다.

Blob 과 마찬가지로 Clob 도 Java 26 부터 AutoCloseable 을 확장하고, 기본 close() 메서드는 free() 를 호출한다.[51] JdbcHelloWorld 의 메서드는 받은 Clob 을 해제하지 않고, 실제 드라이버로 확인하는 시험들도 connection.createClob() 으로 만든 Clob 에 대해 free() 나 close() 를 호출하지 않는다.

java.sql.SQLOutput

java.sql.SQLOutput 은 사용자 정의 SQL 형 (UDT, user-defined type) 의 값을 데이터베이스에 기록할 때 쓰는 출력 스트림을 나타내는 인터페이스이다.[55] UDT 를 자바 클래스로 대응시키면 그 클래스는 SQLData 를 구현하고, 드라이버는 값을 기록할 때 SQLData.writeSQL(SQLOutput) 에 SQLOutput 을 건넨다. writeSQL 은 받은 SQLOutput 의 writeXxx(value) 메서드로 UDT 의 속성을 선언된 순서대로 하나씩 기록한다. 메서드는 속성의 이름이나 번호를 받지 않는다. 호출할 때마다 다음 속성에 기록한다.

JdbcHelloWorld 의 메서드들은 SQLOutput 을 확장한 형(T)의 값을 받아서, hello, world 를 다음 속성의 값으로 기록한 후, 받은 SQLOutput 을 그대로 반환한다. 스트림이나 리더를 넘기는 메서드는 그것을 닫지 않는다. 메서드가 반환한 뒤에도 드라이버가 읽을 수 있기 때문이다.

이 메서드들의 시험은 SQLOutput 을 모의 객체로 두는 JdbcHelloWorld_<동작>_SQLOutput_Test 클래스뿐이다. SQLOutput 을 실제 드라이버로 기록하는 시험은 없다.
