java.lang.foreign.MemorySegment

책의 java.lang.foreign 절은 MemorySegment 의 메서드 가운데 크기를 확인하는 byteSize() 와, 자바 배열의 바이트를 세그먼트로 옮기는 정적 메서드 copy(…​) 만 다룬다. 여기서는 세그먼트를 얻는 다른 방법과 부분 범위, 그리고 세그먼트를 파일과 C 함수에 잇는 예를 모았다.

아래 예제의 service() 는 set(byte[]) 가 hello, world 바이트를 채우도록 미리 스텁해 둔 HelloWorld 이며, copy(MemorySegment) 는 책에서 구현한 대로 그 바이트를 세그먼트의 처음 12 바이트에 기록한다.

세그먼트를 얻는 다른 방법과 부분 범위

MemorySegment 는 Arena 의 allocate(…​) 로 받거나 자바 배열을 MemorySegment.ofArray(…​) 로 감싸 받는 것 말고도, ByteBuffer 를 MemorySegment.ofBuffer(…​) 로 감싸 받을 수 있다.[1] 출처가 어디든 asSlice(…​) 가 그 안의 부분 범위만 가리키는 새 세그먼트를 돌려준다.[2] 슬라이스는 원본과 같은 저장소를 공유하며, 새 저장소를 만들지 않는다.

파일에 매핑한 메모리 영역에 쓰기

FileChannel.map(MapMode, long, long, Arena) 는 파일의 한 범위를 메모리에 매핑한 MemorySegment 를 돌려준다.[3] 이 매핑 세그먼트에 HelloWorld 의 copy(MemorySegment) 로 쓰면, 바이트들이 매핑 영역을 거쳐 디스크 파일에 그대로 기록된다. 자바 측의 추가 I/O 호출 없이 외부 메모리와 파일이 직접 이어지는 예이다.

FileChannel.map(READ_WRITE, …​) 으로 얻은 세그먼트에 copy(…​) 한 결과가 파일 내용과 일치한다
final var path = tempDir.resolve("hello.bin");
try (var channel = FileChannel.open(path, StandardOpenOption.CREATE,
                                    StandardOpenOption.READ,
                                    StandardOpenOption.WRITE);
     var arena = Arena.ofShared()) {
    final var segment = channel.map(FileChannel.MapMode.READ_WRITE,
                                    0L, HelloWorld.BYTES, arena);
    service().copy(segment);
    segment.force();
}
assertEquals(HELLO_WORLD_STRING,
             Files.readString(path, StandardCharsets.US_ASCII));

segment.force() 가 매핑 영역에 쓴 내용을 저장 장치에 기록하고, try 블록을 벗어나며 Arena 가 닫히는 순간 매핑이 해제된다 (unmap). 그 뒤 try 블록 바깥에서 같은 파일을 자바 측에서 다시 읽어 비교한다.

C 표준 라이브러리에서 세그먼트 내용 확인

외부 메모리 세그먼트의 시작 주소는 그 영역의 실제 주소이므로, C 표준 라이브러리의 함수에 그대로 넘길 수 있다. Linker.nativeLinker() 가 운영체제의 libc 에서 심볼을 찾아 다운콜 핸들로 감싸고,[4] handle.invoke(segment) 가 세그먼트의 시작 주소를 그대로 인자로 넘긴다. 책의 java.lang.foreign 절에서는 이 방법으로 C 의 puts 를 불러 hello, world 를 인쇄했다. 아래 두 예는 copy(MemorySegment) 로 채운 세그먼트의 내용을 자바가 아닌 C 측에서 다시 확인한다.

size_t strlen(const char*)

strlen 은 '\0' 종결 문자열의 길이 (종결자를 제외한 바이트 수) 를 돌려준다.[5] 반환 값이 12 인지를 확인하여, copy(…​) 가 세그먼트의 첫 12 바이트만 채우고 13 번째 바이트 ('\0') 를 건드리지 않았음을 보인다.

copy(…​) 한 세그먼트를 strlen 에 넘기면 그 길이가 12 이다
try (var arena = Arena.ofConfined()) {
    final var segment = arena.allocate(HelloWorld.BYTES + 1); (1)
    service().copy(segment);
    final var linker = Linker.nativeLinker();
    final var handle = linker.downcallHandle(
            linker.defaultLookup().find("strlen").orElseThrow(),
            FunctionDescriptor.of(ValueLayout.JAVA_LONG, ValueLayout.ADDRESS)
    );
    final var len = (long) handle.invoke(segment);
    assertEquals(HelloWorld.BYTES, len);
}
1 '\0' 종결자 한 바이트를 둘 공간을 더 확보한다. arena.allocate(…​) 가 돌려주는 외부 메모리는 처음부터 모두 0 이므로 마지막 바이트가 종결자로 남는다.

int memcmp(const void*, const void*, size_t)

memcmp 는 두 메모리 영역의 처음 count 바이트를 비교하여, 동일하면 0 을, 다르면 첫 다른 바이트의 부호 (음수 / 양수) 를 돌려준다.[6] 세그먼트의 첫 12 바이트와 C 측에서 별도로 만든 "hello, world" 영역을 비교하여, 두 바이트열이 비트 단위로 같음을 보인다. 종결자를 거치지 않으므로, 이 검증은 세그먼트를 12 바이트로 잡고 진행한다.

copy(…​) 한 세그먼트의 첫 12 바이트가 "hello, world" 와 비트 단위로 같다
try (var arena = Arena.ofConfined()) {
    final var segment = arena.allocate(HelloWorld.BYTES);
    service().copy(segment);
    final var linker = Linker.nativeLinker();
    final var handle = linker.downcallHandle(
            linker.defaultLookup().find("memcmp").orElseThrow(),
            FunctionDescriptor.of(
                    ValueLayout.JAVA_INT,
                    ValueLayout.ADDRESS,
                    ValueLayout.ADDRESS,
                    ValueLayout.JAVA_LONG
            )
    );
    final var expected = arena.allocateFrom("hello, world", StandardCharsets.US_ASCII);
    final var result = (int) handle.invoke(segment, expected, (long) HelloWorld.BYTES);
    assertEquals(0, result, "Memory content should match 'hello, world'");
}

java.lang.foreign.Arena

책은 Arena 의 정적 팩터리 메서드 가운데 ofConfined() 만 쓰고, 메서드는 allocate(long) 과 (try-with-resources 구문을 통한) close() 만 쓴다.[7] 정적 팩터리 메서드는 모두 네 가지이며, 각각 수명과 접근할 수 있는 스레드가 다르다.

팩터리 수명 접근 스레드 비고

close() 호출까지

가장 빠르고 안전하며, 단일 스레드에서 외부 메모리를 다룰 때 먼저 쓴다.

ofShared()

close() 호출까지

모든 스레드

close() 가 다른 스레드의 사용 종료를 기다리느라 동기화 비용이 든다.

ofAuto()

가비지 컬렉터가 회수할 때까지

모든 스레드

close() 가 적용되지 않는다 (호출하면 UnsupportedOperationException 이 던져진다). 수명을 명시적으로 관리하지 않을 때 쓴다.

global()

JVM 전체 수명

모든 스레드

항상 살아 있는 단일 인스턴스이다 (close() 를 호출하면 UnsupportedOperationException 이 던져진다). MemorySegment.NULL 같은 상수가 이 영역에 속한다.

Arena 가 직접 선언하는 메서드는 다음과 같다.

메서드 설명

MemorySegment allocate(long byteSize, long byteAlignment)

이 Arena 가 관리하는 영역에서 byteSize 바이트짜리 새 MemorySegment 를 할당하여 돌려준다. 시작 주소는 byteAlignment 의 배수가 되도록 정렬된다.

MemorySegment.Scope scope()

이 Arena 가 만들어 내는 모든 MemorySegment 의 수명을 표현하는 Scope 를 돌려준다.

void close()

이 Arena 와, 그것이 만들어 낸 모든 MemorySegment 를 한꺼번에 닫는다. 이후 그 세그먼트에 접근하면 IllegalStateException 이 던져진다.
