책의 java.io 절은 OutputStream 의 확장 클래스 가운데 FileOutputStream 만 다룬다. 아래 두 절은 메모리와 파이프를 대상으로 하는 다른 확장 클래스에 HelloWorld 의 write(OutputStream) 으로 기록해 본다. 예제의 service() 는 write(OutputStream) 이 주어진 스트림에 hello, world 의 12 바이트를 기록하도록 미리 스텁해 둔 HelloWorld 이다.

java.io.ByteArrayOutputStream

java.io.ByteArrayOutputStream 은 메모리 상의 바이트 배열에 기록하는 OutputStream 의 확장 클래스이다.[1]

java.io.ByteArrayOutputStream
package java.io;

public class ByteArrayOutputStream extends OutputStream {

    ...
}

메모리 내부의 바이트 배열에만 기록하므로 비워야 할 버퍼나 해제할 자원이 없다. flush() 메서드는 (아무 일도 하지 않는) OutputStream#flush() 의 기본 구현을 그대로 쓰고, close() 메서드는 (역시 아무 일도 하지 않는 채로) 재정의되어 있다. try-with-resources 블록이나 명시적인 flush()/close() 호출은 동작상 필요하지 않지만, 다른 OutputStream 구현과의 일관성을 위해 사용한다.

아래는 실제 ByteArrayOutputStream 으로 write(stream) 을 확인하는 예시이다.

ByteArray(In|Output)Stream
try (var baos = new ByteArrayOutputStream(HelloWorld.BYTES)) { (1)
    service().write(baos).flush();
    assertEquals(HelloWorld.BYTES, baos.size());               (2)
    try (var bais = new ByteArrayInputStream(baos.toByteArray())) {
        final var bytes = bais.readAllBytes();
        assertArrayEquals(hello_world_byte_array(), bytes);    (3)
        final var decoded = new String(bytes, StandardCharsets.US_ASCII);
        assertEquals(HELLO_WORLD_STRING, decoded);             (4)
    }
}
1 알고 있는 길이(HelloWorld.BYTES, 즉 12 바이트)에 맞춰 내부 버퍼 용량을 잡고 ByteArrayOutputStream 을 연다.
2 write(stream) 으로 기록된 바이트 수가 정확히 HelloWorld.BYTES 인지 확인한다.
3 다시 읽어 낸 바이트 배열이 기대한 hello, world 바이트와 같은지 확인한다.
4 그 바이트를 US-ASCII 로 디코딩한 문자열이 hello, world 와 같은지 확인한다.

java.io.PipedOutputStream

java.io.PipedOutputStream 은 연결된 java.io.PipedInputStream 으로 바이트를 보내는 OutputStream 의 확장 클래스이다.[2]

java.io.PipedOutputStream
package java.io;

public class PipedOutputStream extends OutputStream {

    ...
}

OutputStream 을 물을 내보낼 수 있는 출수관(出水管)이라고 생각해 본다면, InputStream 은 물이 들어오는 입수관(入水管)으로 볼 수 있다.

Figure 1. 출수관 (OutputStream)
Figure 2. 입수관 (InputStream)

이제 출수관과 입수관을 파이프로 연결하면, 출수관을 통해 내보낸 물을 입수관에서 받을 수 있다. 한 번에 보낼 수 있는 물의 양은 파이프의 용량(capacity)에 의해 제한되며, 파이프가 가득 차 있으면 입수관에서 물을 소비하여 빈 공간이 생긴 후에야 다시 보낼 수 있다.

Figure 3. 파이프로 연결된 출수관과 입수관

java.io.PipedOutputStream 과 java.io.PipedInputStream 은 위와 같이 파이프로 연결된 (Out|In)putStream 을 나타낸다. PipedOutputStream 에 기록한 바이트들은 연결된 PipedInputStream 의 내부 버퍼에 쌓이고, 그쪽에서 읽기로 꺼낼 수 있다.

두 스트림은 보통 별도의 스레드에서 사용한다. 쓰기 측과 읽기 측을 분리해 한쪽이 기록하는 동안 다른 쪽이 읽어 가는 연속적인 데이터 흐름을 만들기 위해서다. 버퍼가 가득 차면 쓰기 측이 대기하고, 비어 있으면 읽기 측이 대기하면서 두 스레드가 자연스럽게 보조를 맞춘다.

PipedOutputStream 과 PipedInputStream 을 직접 연결해 write(stream) 을 확인하는 두 예시를 본다.

먼저, 파이프 용량이 보낼 바이트 수보다 크거나 같으면 한 스레드에서 끝낼 수 있다. 기록이 버퍼를 넘치지 않아 막히지 않기 때문이다.

파이프 용량이 충분할 때
try (var pos = new PipedOutputStream();
     var pis = new PipedInputStream(HelloWorld.BYTES)) { (1)
    pos.connect(pis);                                    (2)
    service().write(pos).flush();                        (3)
    final var bytes = pis.readNBytes(HelloWorld.BYTES);  (4)
    final var string = new String(bytes, StandardCharsets.US_ASCII);
    assertEquals(HELLO_WORLD_STRING, string);
}
1 12 바이트를 모두 담을 수 있는 용량(HelloWorld.BYTES)으로 입수관을 만든다.
2 출수관과 입수관을 연결한다.
3 같은 스레드에서 기록한다. 버퍼가 충분해 막히지 않는다.
4 입수관에서 12 바이트를 읽어 문자열로 확인한다.

다음으로, 파이프 용량이 보낼 바이트 수보다 작으면 한 스레드만으로는 끝낼 수 없다. 기록과 읽기를 같은 스레드에서 하면, 버퍼가 가득 찬 채 쓰기가 막혀 읽기로 넘어가지 못한다(교착). 그래서 기록을 다른 스레드로 옮겨, 한쪽이 기록하는 동안 이쪽에서 읽어 버퍼를 비워 준다.

파이프 용량이 부족할 때, 기록은 다른 스레드에서
final var pipeSize = ThreadLocalRandom.current().nextInt(1, HelloWorld.BYTES); (1)
try (var pos = new PipedOutputStream();
     var pis = new PipedInputStream(pipeSize)) {
    pos.connect(pis);
    Thread.ofPlatform().start(() -> {                                          (2)
        try {
            service().write(pos).flush();
        } catch (final IOException ioe) {
            throw new RuntimeException(ioe);
        }
    });
    final var bytes = pis.readNBytes(HelloWorld.BYTES);                        (3)
    final var string = new String(bytes, StandardCharsets.US_ASCII);
    assertEquals(HELLO_WORLD_STRING, string);
}
1 12 보다 작은 파이프 용량을 무작위로 골라, 일부러 버퍼를 부족하게 만든다.
2 기록을 별도의 스레드에서 수행한다. 버퍼가 차면 이 스레드가 대기한다.
3 이 스레드에서 읽어 버퍼를 비우면, 막혀 있던 기록이 다시 진행된다.

java.io.Writer

책의 java.io 절은 Writer 의 메서드 가운데 flush() 만 따로 다룬다. HelloWorld#write(Writer) 는 받은 Writer 를 append(Appendable) 에 그대로 넘기므로, 실제로 hello, world 의 각 char 를 받는 것은 Writer 가 Appendable 로서 구현하는 append(char) 이다.[3]

Writer append(char c)

char 하나를 덧붙인 뒤 자기 자신을 반환한다. 기본 구현은 write(int) 를 부르고, write(int) 는 주어진 값의 하위 16 비트 (UTF-16 코드 단위 하나) 를 내부 char[] 버퍼의 첫 칸에 담아 추상 메서드 write(char[], int, int) 를 길이 1 로 호출한다. 결국 모든 기록이 이 3-인자 메서드로 모이므로, Writer 를 확장하는 클래스는 그 하나를 반드시 구현해야 한다.[4]
