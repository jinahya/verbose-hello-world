javax.crypto

javax.crypto 는 암호 연산을 위한 패키지이다.[1] 암호화와 복호화를 하는 Cipher, 메시지 인증 코드를 계산하는 Mac, 그리고 두 클래스가 쓰는 비밀 키를 만드는 KeyGenerator / SecretKeyFactory 를 제공한다. java.security 와 함께 자바 암호 아키텍처 (JCA) 를 이룬다. 이 절에서는 Cipher 와 Mac 을 다룬다.

javax.crypto.Cipher

javax.crypto.Cipher 는 암호 변환 (cryptographic transformation) 의 표준 추상화로, 같은 클래스로 암호화 (ENCRYPT_MODE) 와 복호화 (DECRYPT_MODE) 를 모두 수행한다.[2] getInstance("AES/CBC/PKCS5Padding") 처럼 변환 문자열로 알고리즘, 모드, 패딩을 한꺼번에 지정하고, init(opmode, key[, params]) 로 동작 모드와 키를 설정한 뒤, update(…​) 로 입력을 누적하면서 부분 출력을 받고 doFinal(…​) 로 마무리한다. 즉 update 와 doFinal 두 단계로 동작하는 상태 기계이다.

javax.crypto.Cipher
package javax.crypto;

public class Cipher {

    public final int update(byte[] input, int inputOffset, int inputLen,
                            byte[] output, int outputOffset)
            throws ShortBufferException { ... }

    public final int update(ByteBuffer input, ByteBuffer output)
            throws ShortBufferException { ... }

    public final byte[] doFinal(byte[] input)
            throws IllegalBlockSizeException, BadPaddingException { ... }

    ...
}

Cipher.getInstance(String) 에 넘기는 변환 (transformation) 문자열은 "algorithm/mode/padding" 또는 "algorithm" 형식이다 (예: "AES/CBC/PKCS5Padding", "RSA/ECB/OAEPWithSHA-256AndMGF1Padding", "ChaCha20-Poly1305"). 알고리즘만 적으면 모드와 패딩은 제공자 (provider) 의 기본값을 따르므로, 이식성과 보안을 위해 세 요소를 모두 적는 편이 좋다.

Table 1. 변환 문자열의 세 요소
요소 의미 예

algorithm

암호 알고리즘 자체. 키 길이와 동작 방식 (대칭 / 비대칭, 블록 / 스트림) 을 결정한다.

AES, RSA, ChaCha20-Poly1305

mode

블록 암호를 임의 길이 입력에 적용하는 운영 방식. ChaCha20-Poly1305 나 RSA 에서는 형식상 붙는 이름이거나 적용되지 않는다.

ECB, CBC, GCM

padding

입력을 알고리즘이 요구하는 형태로 맞추는 인코딩. 블록 암호에서는 마지막 블록을 채우고, RSA 에서는 메시지를 무작위화하고 정형화한다.

NoPadding, PKCS5Padding, OAEPWithSHA-256AndMGF1Padding

ECB 는 각 블록을 독립적으로 암호화하므로 같은 평문 블록이 늘 같은 암호문 블록이 되어 실제 사용에서는 피한다. CBC 는 각 블록을 직전 암호문 블록과 XOR 한 뒤 암호화하며, 첫 블록을 위한 IV (Initialization Vector) 가 필요하다. GCM 은 카운터 모드로 암호화하면서 인증 태그를 함께 만드는 AEAD (Authenticated Encryption with Associated Data) 모드다. ChaCha20-Poly1305 도 AEAD 변환이다. AEAD 변환은 암호문에 인증 태그를 붙여 기밀성과 무결성을 함께 제공하므로 별도의 MAC 이 필요 없다.

int update(byte[] input, int inputOffset, int inputLen, byte[] output, int outputOffset)

input 의 inputOffset 부터 inputLen 바이트를 누적시키고, 그 사이에 만들어진 부분 출력을 output 의 outputOffset 위치부터 직접 기록한 뒤 기록한 바이트 수를 돌려준다.[3] output 의 outputOffset 이후 공간이 모자라면 ShortBufferException 을 던진다. HelloWorld#update(Cipher, byte[], int, IntConsumer) 가 이 메서드를 부른다.

부분 출력이 생기는 시점은 변환마다 다르다. 블록 암호 (AES, DESede) 의 출력 시점은 운영 모드와 패딩에 따라 다르다. 예를 들어 내부에 대기 중인 입력이 없는 ECB 또는 CBC 모드에서 16 바이트 블록의 AES 에 12 바이트만 넣으면 돌려주는 값은 0 이다. AEAD 변환에서 복호화할 때는 인증 태그를 확인하기 전까지 출력이 doFinal(…​) 로 미뤄지고, RSA 는 메시지 전체가 모이기 전까지 출력이 없다. 따라서 호출자는 돌려받은 길이가 0 인 경우도 처리할 수 있어야 한다.

int update(ByteBuffer input, ByteBuffer output)

input 의 position 부터 limit 까지 남은 바이트를 누적시키고, 부분 출력을 output 의 현재 position 부터 직접 기록한 뒤 기록한 바이트 수를 돌려준다. 두 버퍼의 position 은 각각 읽은 만큼, 기록한 만큼 나아간다.[4] output 에 남은 공간이 모자라면 ShortBufferException 을 던진다. HelloWorld#update(Cipher, ByteBuffer, IntConsumer) 가 이 메서드를 부른다.

byte[] doFinal(byte[] input)

input 을 마지막으로 누적시킨 뒤 남은 출력과 패딩, 인증 태그까지 모두 내보낸 결과를 새 배열로 돌려준다.[5] 호출이 끝나면 인스턴스는 마지막으로 init(…​) 한 직후의 상태로 돌아간다.

NoPadding 변환에서 누적된 입력 길이가 블록 크기의 배수가 아니면 IllegalBlockSizeException 을 던진다. PKCS5Padding 은 암호화할 때 패딩 바이트를 채우고 복호화할 때 제거하므로 임의 길이 입력을 처리할 수 있다. AEAD 변환으로 복호화할 때는 이 단계에서 인증 태그를 확인하며, 암호문이나 AAD 가 바뀌었다면 AEADBadTagException 을 던진다.

javax.crypto.Mac

javax.crypto.Mac 은 MAC (Message Authentication Code) 을 계산하는 엔진 클래스 (engine class) 다.[6] MAC 은 메시지의 무결성 (integrity) 과 출처 인증 (data-origin authentication) 을 함께 보장하는 고정 길이의 짧은 태그 (tag) 다. 출처 인증은 "메시지가 같은 키를 가진 어느 한쪽에서 왔다" 는 사실에 한정된다.

javax.crypto.Mac
package javax.crypto;

public class Mac implements Cloneable {

    public final void update(byte[] input) throws IllegalStateException { ... }

    ...
}

기밀성 (confidentiality) 은 제공하지 않는다. 메시지 자체는 평문으로 둔 채, 받는 쪽이 같은 키로 같은 알고리즘을 돌려 같은 태그가 나오는지를 비교해 위·변조 여부를 판별한다. 송수신자가 같은 비밀 키를 나눠 가지므로, 발신자 한 명을 특정하고 부인 방지 (non-repudiation) 까지 얻으려면 비대칭 키를 쓰는 java.security.Signature 가 필요하다.

가장 흔한 구현은 HMAC (Hash-based MAC) 으로, 임의의 해시 함수를 키와 결합해 MAC 으로 만드는 일반 구성이다.[7] JCA 의 표준 이름은 Hmac 에 해시 이름을 붙인 HmacSHA256, HmacSHA512 같은 형태다.[8]

사용 순서는 네 단계다. getInstance(algorithm) 로 인스턴스를 얻고, init(key) 로 키를 설정한 뒤, update(byte[]) 로 입력을 누적해 doFinal() 로 태그를 받는다.

void update(byte[] input)

배열 전체의 바이트를 누적시킨다. update(input, 0, input.length) 와 같다.[9] 반환값이 없으며 (void), 인스턴스가 초기화되어 있지 않으면 IllegalStateException 을 던진다. update(a) 다음에 update(b) 를 부른 결과는 a 와 b 를 이어 붙인 배열로 한 번 부른 결과와 같다. HelloWorld#update(Mac) 은 hello, world 12 바이트를 이 메서드에 한 번에 넘긴다.

update(Cipher, byte[], int, IntConsumer)

HelloWorld 인터페이스의 update(Cipher, byte[], int, IntConsumer) 메서드는 Cipher 를 확장한 형(T)의 인스턴스에 hello, world 12 바이트를 누적시키고, 산출 바이트는 호출자가 건넨 출력 배열의 지정한 오프셋부터 채운 뒤, 채워진 바이트의 개수를 별도의 IntConsumer 에 전달한다.

Cipher.update(byte[], int, int, byte[], int) 가 그 위치에 부분 출력을 쓰고 산출 길이를 int 로 반환한다. 이 메서드는 그 반환값을 호출자에게 직접 돌려주지 않고 콜백으로 넘긴다는 점이 다르다. ByteBuffer 변형은 같은 뼈대를 따르며, 산출 위치만 byte[] + offset 에서 ByteBuffer 로 바뀐다.

HelloWorld#update(Cipher, byte[], int, IntConsumer)
<T extends Cipher> T update(T cipher, byte[] output, int offset, IntConsumer consumer)
        throws ShortBufferException

  • 주어진 암호 객체를 hello, world 바이트들로 갱신하고, 그 결과를 주어진 출력 배열의 offset 위치부터 기록한다.

  • T (타입 매개변수): 호출자가 건넨 Cipher 의 구체 타입. cipher 인자가 그대로 이 T 타입으로 반환되므로, 호출자는 자기가 건넨 서브타입을 캐스트 없이 다시 받을 수 있다.

  • cipher (매개변수): hello, world 12 바이트를 누적시킬 Cipher. 호출 전에 init(opmode, key, …​) 로 초기화되어 있어야 한다.

  • output (매개변수): cipher.update(…​) 가 산출 바이트를 쓸 출력 배열.

  • offset (매개변수): output 안에서 산출 결과를 쓰기 시작할 오프셋 (0 이상, output.length 미만).

  • consumer (매개변수): cipher.update(array, 0, BYTES, output, offset) 가 돌려준 산출 바이트 수를 받을 IntConsumer.

  • 반환값: 주어진 cipher.

  • NullPointerException (예외): cipher 또는 consumer 가 null 인 경우.

  • ShortBufferException (예외): output 의 offset 이후 남은 공간이 cipher.update(…​) 가 산출할 바이트 수보다 적은 경우.

  • 기본 구현: 다음과 같이 동작한다.

    • cipher 와 consumer 의 null 을 즉시 검사하여 NullPointerException 을 던진다.

    • 길이가 12 인 byte[] 를 만들고 set(array) 로 hello, world 바이트를 채운다.

    • 채워진 배열과 output / offset 으로 cipher.update(array, 0, BYTES, output, offset) 를 호출하여 산출 바이트 수를 받는다.

    • 위에서 받은 산출 바이트 수를 consumer.accept(…​) 에 그대로 전달한다.

set(array) 로 채운 길이 12 의 배열을 cipher.update(array, 0, BYTES, output, offset) 에 넘기고, 반환된 바이트 수를 consumer 에 전달하면 된다. null 검증부터 cipher 반환까지 모든 단계가 이미 들어 있어 본문 그대로 동작한다.

HelloWorld#update(cipher, output, offset, consumer)
default <T extends Cipher> T update(T cipher, byte[] output, int offset, IntConsumer consumer)
        throws ShortBufferException {
    Objects.requireNonNull(cipher, "cipher is null");
    Objects.requireNonNull(consumer, "consumer is null");
    final var array = new byte[BYTES];
    set(array);
    final var result = cipher.update(array, 0, BYTES, output, offset);
    consumer.accept(result);
    return cipher;
}

HelloWorld_Update_Cipher_Output_Offset_Consumer_Test

update(Cipher, byte[], int, IntConsumer) 메서드를 검증하는 시험 클래스이다.

set(array) 로 채워진 배열이 cipher.update(array, 0, BYTES, output, offset) 에 그대로 전달되고, 그 호출이 돌려준 산출 길이가 다시 consumer.accept(…​) 로 전달되는지를 검증한다.

HelloWorld_Update_Cipher_Output_Offset_Consumer_Test#__()
final var service = set_array_returns_the_array(service());                          (1)
final var cipher = mock(Cipher.class);
final var output = new byte[HelloWorld.BYTES << 1];                           // 24
final var offset = ThreadLocalRandom.current().nextInt(HelloWorld.BYTES + 1); // [0..12]
final var bytes = ThreadLocalRandom.current().nextInt(HelloWorld.BYTES + 1);  // [0..12]
doReturn(bytes).when(cipher)
        .update(any(byte[].class), anyInt(), anyInt(), any(byte[].class), anyInt()); (2)
final var consumer = mock(IntConsumer.class);
// ------------------------------------------------------------------------------------ when
final var result = service.update(cipher, output, offset, consumer);
// ------------------------------------------------------------------------------------ then
final var array = set_array12_invoked_once(service);                                 (3)
verify(cipher).update(array, 0, HelloWorld.BYTES, output, offset);                   (4)
verify(consumer).accept(bytes);                                                      (5)
assertSame(cipher, result);
1 service.set(array) 가 호출되면 그 배열을 그대로 돌려주도록 스텁한다.
2 cipher.update(array, 0, BYTES, output, offset) 호출이 임의의 산출 길이 bytes 를 돌려주도록 스텁한다.
3 service.set(…​) 이 길이 12 의 배열로 정확히 한 번 호출되었는지 검증하고, 그때 전달된 배열 자체를 돌려받는다.
4 바로 그 배열과 output / offset 으로 cipher.update(…​) 의 5-인자 오버로드가 호출되었는지 검증한다.
5 스텁이 돌려준 산출 길이가 consumer.accept(…​) 로 그대로 전달되었는지 검증한다.

표준 알고리즘

javax.crypto.Cipher 의 API 문서는 모든 Java 플랫폼 구현이 반드시 지원해야 하는 표준 변환 (transformation) 과 키 크기를 정해 둔다.[10] 아래는 그 변환과 키 크기마다 Cipher 를 암호화 모드로 초기화하고, update(Cipher, byte[], int, IntConsumer) 로 hello, world 를 넣은 뒤 doFinal(…​) 로 마무리한 암호문을 출력한 결과이다.

표준 변환별 hello, world 의 암호문

                 AES/CBC/PKCS5Padding |                  128 |  16  128 | SE70...Cw==
                    AES/ECB/NoPadding |                  128 |  16  128 | MkaX...ww==
                 AES/ECB/PKCS5Padding |                  128 |  16  128 | EjuQ...ZQ==
                    AES/GCM/NoPadding |                  128 |  28  224 | 5Coy...+g==
                    AES/GCM/NoPadding |                  256 |  28  224 | omYk...Sw==

왼쪽부터 변환, 키의 비트 수 (PBE 계열과 ChaCha20-Poly1305 는 비어 있다), 암호문의 바이트 수와 비트 수, Base64 로 인코딩한 암호문의 앞뒤 네 글자이다. AES/CBC/NoPadding 과 AES/ECB/NoPadding 은 패딩을 하지 않으므로, 시험이 12 바이트 뒤에 0 을 4 바이트 덧붙여 블록 크기 (16 바이트) 를 맞춘 뒤 마무리한다. AES/GCM/NoPadding 과 ChaCha20-Poly1305 의 28 바이트는 암호문 12 바이트에 16 바이트 인증 태그가 붙은 길이이고, RSA OAEP 의 암호문은 키의 모듈러스와 같은 길이 (1024 비트면 128 바이트, 2048 비트면 256 바이트) 가 된다. 키와 IV 를 실행할 때마다 새로 만들므로 암호문의 값은 실행마다 다르다.

update(Cipher, ByteBuffer, IntConsumer)

HelloWorld 인터페이스의 update(Cipher, ByteBuffer, IntConsumer) 메서드는 Cipher 를 확장한 형(T)의 인스턴스에 hello, world 12 바이트를 누적시키고, 그 호출이 산출한 바이트를 호출자가 건넨 출력 버퍼에 채운 뒤, 채워진 바이트의 개수를 별도의 IntConsumer 에 전달한다.

byte[] + offset 변형과 뼈대는 같지만, 출력 대상을 byte[] 배열과 오프셋 대신 ByteBuffer 로 지정한다는 점이 다르다. Cipher.update(ByteBuffer, ByteBuffer) 가 입력 버퍼에서 바이트를 읽어 출력 버퍼의 현재 position 부터 부분 출력을 쓰고, 그 길이를 int 로 반환한다. 이 메서드는 그 반환값을 호출자에게 직접 돌려주는 대신 콜백으로 처리한다.

HelloWorld#update(Cipher, ByteBuffer, IntConsumer)
<T extends Cipher> T update(T cipher, ByteBuffer output, IntConsumer consumer)
        throws ShortBufferException

  • 주어진 암호 객체를 hello, world 바이트들로 갱신하고, 그 결과를 주어진 출력 버퍼에 기록한다.

  • T (타입 매개변수): 호출자가 건넨 Cipher 의 구체 타입. cipher 인자가 그대로 이 T 타입으로 반환되므로, 호출자는 자기가 건넨 서브타입을 캐스트 없이 다시 받을 수 있다.

  • cipher (매개변수): hello, world 12 바이트를 누적시킬 Cipher. 호출 전에 init(opmode, key, …​) 로 초기화되어 있어야 한다.

  • output (매개변수): cipher.update(…​) 가 산출 바이트를 쓸 출력 버퍼. 현재 position 부터 채워지고, 그만큼 position 이 진행된다.

  • consumer (매개변수): cipher.update(buffer, output) 가 돌려준 산출 바이트 수를 받을 IntConsumer.

  • 반환값: 주어진 cipher.

  • NullPointerException (예외): cipher 또는 consumer 가 null 인 경우.

  • ShortBufferException (예외): output 의 남은 공간이 cipher.update(buffer, output) 가 산출할 바이트 수보다 적은 경우.

  • 기본 구현: 다음과 같이 동작한다.

    • cipher 와 consumer 의 null 을 즉시 검사하여 NullPointerException 을 던진다.

    • 길이가 12 인 ByteBuffer 를 만들고 put(buffer) 로 hello, world 바이트를 채운 뒤 flip() 으로 읽기 모드로 전환한다.

    • 채워진 입력 버퍼와 output 으로 cipher.update(buffer, output) 를 호출하여 산출 바이트 수를 받는다.

    • 위에서 받은 산출 바이트 수를 consumer.accept(…​) 에 그대로 전달한다.

put(buffer) 로 채운 버퍼를 flip() 한 뒤 cipher.update(buffer, output) 에 넘기고, 반환된 바이트 수를 consumer 에 전달하면 된다. null 검증부터 cipher 반환까지 모든 단계가 이미 들어 있어 본문 그대로 동작한다.

HelloWorld#update(cipher, output, consumer)
default <T extends Cipher> T update(T cipher, ByteBuffer output, IntConsumer consumer)
        throws ShortBufferException {
    Objects.requireNonNull(cipher, "cipher is null");
    Objects.requireNonNull(consumer, "consumer is null");
    final var buffer = ByteBuffer.allocate(BYTES);
    put(buffer);
    buffer.flip();
    final var result = cipher.update(buffer, output);
    consumer.accept(result);
    return cipher;
}

표준 알고리즘

update(Cipher, ByteBuffer, IntConsumer) 로 같은 변환과 키 크기를 돌려도 암호문의 길이, 패딩, 인증 태그는 앞 절 의 결과와 같고, 실행마다 키와 IV 를 새로 만들므로 값만 다르다. 두 오버로드는 산출을 어디에 쓰느냐만 다르다. 배열판은 output[offset] 부터 쓰고 아무 위치도 바꾸지 않는 반면, 버퍼판은 output 의 현재 position() 부터 쓰고 쓴 바이트 수만큼 position 을 전진시킨다. 입력 버퍼의 position 도 limit 까지 전진한다.

update(Mac)

HelloWorld 인터페이스의 update(Mac) 메서드는 Mac 을 확장한 형(T)의 인스턴스에 hello, world 12 바이트를 한 번에 누적시킨다. 태그는 호출자가 원하는 시점에 그 Mac 의 doFinal() 을 호출해 가져간다.

HelloWorld#update(Mac)
<T extends Mac> T update(T mac)

  • 주어진 MAC 을 hello, world 바이트들로 갱신한다.

  • T (타입 매개변수): 호출자가 건넨 Mac 의 구체 타입. mac 인자가 그대로 이 T 타입으로 반환되므로, 호출자는 자기가 건넨 서브타입을 캐스트 없이 다시 받을 수 있다.

  • mac (매개변수): hello, world 12 바이트를 누적시킬 Mac. 호출 전에 init(key[, params]) 로 초기화되어 있어야 한다.

  • 반환값: 주어진 mac.

  • NullPointerException (예외): mac 이 null 인 경우.

  • 기본 구현: 다음과 같이 동작한다.

    • mac 의 null 을 즉시 검사하여 NullPointerException 을 던진다.

    • 길이가 12 인 byte[] 를 만들고 set(array) 로 hello, world 바이트를 채운다.

    • 채워진 배열 전체를 한 번에 mac.update(array) 로 공급한다. 분할 누적이 아니라 한 번의 호출이다.

set(array) 로 채운 길이 12 의 배열을 mac.update(array) 로 한 번에 공급하면 된다. update(MessageDigest) 와 같은 형태이다. null 검증부터 mac 반환까지 모든 단계가 이미 들어 있어 본문 그대로 동작한다.

HelloWorld#update(mac)
default <T extends Mac> T update(final T mac) {
    Objects.requireNonNull(mac, "mac is null");
    final var array = new byte[BYTES];
    set(array);
    mac.update(array); (1)
    return mac;
}
1 Mac.update(byte[]) 의 반환 타입은 void 다. 누적된 입력으로부터 태그를 얻으려면 호출자가 별도로 mac.doFinal() 을 호출해야 한다.

표준 알고리즘

javax.crypto.Mac 의 API 문서는 모든 Java 플랫폼 구현이 반드시 지원해야 하는 표준 알고리즘으로 HmacSHA1, HmacSHA256, PBEWithHmacSHA256 세 가지를 정해 둔다.[11] 아래는 이 세 알고리즘마다 키를 만들어 Mac 을 초기화하고, update(Mac) 로 hello, world 를 넣은 뒤 doFinal() 로 얻은 태그를 출력한 결과이다. PBEWithHmacSHA256 은 패스워드에서 키를 유도하므로 솔트와 반복 횟수를 PBEParameterSpec 으로 함께 넘긴다.

표준 알고리즘별 hello, world 의 MAC 태그
         HmacSHA1                      (  20) WUMU...qOA=
       HmacSHA256                      (  32) zNrH...e8o=
PBEWithHmacSHA256                      (  32) C+Sz...AD8=

왼쪽부터 알고리즘, 태그의 바이트 수, Base64 로 인코딩한 태그의 앞뒤 네 글자이다. 태그의 길이는 바탕 해시 함수의 출력 길이와 같다. 키를 실행할 때마다 새로 만들므로 태그의 값은 실행마다 다르다.

updateAAD(Cipher)

HelloWorld 인터페이스의 updateAAD(Cipher) 메서드는 Cipher 를 확장한 형(T)의 인스턴스에 hello, world 12 바이트를 AAD (Additional Authenticated Data) 로 공급한다. AAD 는 AEAD 변환 (AES/GCM/NoPadding, ChaCha20-Poly1305) 이 암호화하지 않으면서 인증 태그에는 포함하는 데이터이다. 암호문과 함께 보내되 감출 필요는 없는 헤더 같은 값을 변조로부터 지킬 때 쓴다.[12]

HelloWorld#updateAAD(Cipher)
<T extends Cipher> T updateAAD(T cipher)

  • 주어진 암호기의 AAD (Additional Authenticated Data) 를 hello, world 바이트들로 갱신한다.

  • T (타입 매개변수): 호출자가 건넨 Cipher 의 구체 타입. cipher 인자가 그대로 이 T 타입으로 반환된다.

  • cipher (매개변수): AAD 를 갱신할 Cipher. 호출 전에 AEAD 변환으로 초기화되어 있어야 한다.

  • 반환값: 주어진 cipher.

  • NullPointerException (예외): cipher 가 null 인 경우.

  • 기본 구현: 길이가 12 인 배열을 set(array) 로 채우고, cipher.updateAAD(array) 를 호출한다.

update(Mac) 과 같은 형태이다. set(array) 로 채운 길이 12 의 배열을 cipher.updateAAD(array) 로 한 번에 공급한다. null 검증부터 cipher 반환까지 모든 단계가 이미 들어 있어 본문 그대로 동작한다.

HelloWorld#updateAAD(cipher)
default <T extends Cipher> T updateAAD(final T cipher) {
    Objects.requireNonNull(cipher, "cipher is null");
    final var array = new byte[BYTES];
    set(array);
    cipher.updateAAD(array); (1)
    return cipher;
}
1 AAD 는 암호화할 데이터보다 먼저 공급해야 한다. update(…​) 나 doFinal(…​) 로 데이터를 넣기 시작한 뒤에 updateAAD(…​) 를 호출하면 IllegalStateException 이 발생한다.

암호화와 복호화 양쪽의 AAD

AAD 는 암호화할 때와 복호화할 때 같은 값을 공급해야 한다. 아래는 AES/GCM/NoPadding 으로 hello, world 를 암호화하고 다시 복호화하는 예이다. 두 쪽 모두 updateAAD(Cipher) 로 같은 AAD 를 공급하므로 복호화의 doFinal(…​) 이 인증 태그 확인을 통과한다. 복호화 쪽 AAD 가 한 바이트라도 다르면 doFinal(…​) 이 AEADBadTagException 을 던진다.

AES/GCM/NoPadding 왕복
final var generator = KeyGenerator.getInstance(ALGORITHM);
generator.init(keysize);
final var key = generator.generateKey();
final AlgorithmParameterSpec params;
{
    final var iv = new byte[GCM_IV_LENGTH];
    ThreadLocalRandom.current().nextBytes(iv);
    params = new GCMParameterSpec(GCM_TAG_LENGTH, iv); (1)
}
final var plaintext = HelloWorld__TestUtils.hello_world_byte_array();
// ----------------------------------------------------------------------------- encrypt
final byte[] ciphertext;
{
    final var cipher = Cipher.getInstance(TRANSFORMATION);
    cipher.init(Cipher.ENCRYPT_MODE, key, params);
    service().updateAAD(cipher);                       (2)
    ciphertext = cipher.doFinal(plaintext);
    printf(TRANSFORMATION, keysize, ciphertext);
}
// ----------------------------------------------------------------------------- decrypt
final byte[] decrypted;
{
    final var cipher = Cipher.getInstance(TRANSFORMATION);
    cipher.init(Cipher.DECRYPT_MODE, key, params);
    service().updateAAD(cipher);                       (3)
    decrypted = cipher.doFinal(ciphertext);
}
// -------------------------------------------------------------------------------- then
assertArrayEquals(plaintext, decrypted);
1 IV 는 12 바이트, 인증 태그는 128 비트로 정한다. 12 바이트는 GCM 에 권장되는 IV 길이이다.
2 암호화 쪽에서 AAD 를 공급한 뒤 평문을 암호화한다.
3 복호화 쪽에서도 같은 AAD 를 공급해야 태그 확인을 통과한다.

ChaCha20-Poly1305 도 같은 과정을 거친다. 키는 256 비트만 쓸 수 있고, GCMParameterSpec 대신 12 바이트 논스를 담은 IvParameterSpec 을 넘긴다.

AEAD 변환별 암호문
             ChaCha20-Poly1305                      (  28) 55AW...0g==
             AES/GCM/NoPadding                  128 (  28) 0KKi...UQ==
             AES/GCM/NoPadding                  256 (  28) lu1Z...vw==

왼쪽부터 변환, AES 키 크기, 암호문의 바이트 수, Base64 로 인코딩한 암호문의 앞뒤 네 글자이다. 두 변환 모두 12 바이트 평문에 16 바이트 인증 태그가 붙어 28 바이트가 된다. AAD 는 태그 계산에만 들어가고 암호문의 길이를 늘리지 않는다. 키와 IV 를 실행할 때마다 새로 만들므로 암호문의 값은 실행마다 다르다.
