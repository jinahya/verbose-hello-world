== JPMS SPI (`provides … with …`)

Add a JPMS-style `ServiceLoader` registration channel alongside the existing
classpath `META-INF/services/…` mechanism, so the book can contrast the two
registration channels using the *same* `ServiceLoader.load(…)` API call.

Discovery rules in JDK 25:

[%unbreakable%autowidth.stretch,frame="none",grid="rows"]
|===
| Provider lives in… | Registered via… | Found when running…

| classpath JAR | `META-INF/services/X` | classpath or module-path (as automatic / unnamed module)
| named module  | `provides X with …` in `module-info` | module-path only
| named module  | `META-INF/services/X` inside the JAR | *ignored* — module system requires `provides`
|===

  registers both providers via the classpath channel.

Missing — add a JPMS registration channel. Pick one:

. *Promote the two providers from `src/test/java` to `src/main/java`* and add
  `provides com.github.jinahya.hello.api.spi.HelloWorldServiceProvider
  with HelloWorldServiceProvider_Impl, HelloWorldServiceProvider_Demo;`
  to the existing main `module-info`. Keep the existing
  `META-INF/services` file so both channels coexist in a single JAR. *Simplest;
  recommended.*
. *New sibling Maven module* (e.g. `02b-verbose-hello-world-lib-spi-jpms`) whose
  `module-info` declares `provides …` and whose only source is the two
  providers. The existing classpath-SPI test stays untouched; a new test in this
  side module loads providers via the module-path. Best separation, more
  boilerplate.
. *Surefire `--patch-module`* — inject a synthetic `module-info` with
  `provides …` for the JPMS test run only. Avoids restructuring sources but the
  mechanism is invisible to a reader of the source tree (poor fit for a teaching
  codebase).

After option 1, add a test pair (same `ServiceLoader.load(…)` body, two
Surefire executions):

* `HelloWorldServiceProvider_Classpath_Test` — runs with the lib JAR on the
  classpath; asserts both providers are resolved via `META-INF/services`.
* `HelloWorldServiceProvider_ModulePath_Test` — runs with the lib JAR on the
  module-path (forked JVM); asserts both providers are resolved via the
  `provides` clause.
