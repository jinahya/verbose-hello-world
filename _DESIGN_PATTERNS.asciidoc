= 디자인 패턴 사용 현황 (design patterns of hello, world & JDK)
:toc: macro

이 파일은 `verbose-hello-world` 코드 프로젝트 안에서 "hello, world" 12 바이트 페이로드를 둘러싸고 등장하는 디자인 패턴들 — GoF 4인방 + JDK 가 정착시킨 관용구들 — 의 실제 사용 지점을 한 테이블에 모아 놓는다. "어느 패턴이 어디서 어떤 형태로 등장했는가" 만 적는다. 평가 (좋다/나쁘다) 나 리팩터링 제안은 적지 않는다.

ID 는 카테고리별로 일련번호를 끊고, 카테고리는 GoF 의 큰 분류 (Creational / Structural / Behavioral) 와 그 외 (JDK 관용구 — Reactive Streams, Async Callback, SPI, DI/IoC, Structured Concurrency 등) 를 따른다.

== 요약

대분류별로 정리하면 다음과 같다 (총 {DP-0001..DP-0008} + {DP-0101..DP-0111} + {DP-0201..DP-0217} + {DP-0301..DP-0311} = **47 항목**).

- *Creational* (8) — Static Factory Method, Fluent Builder (`Thread`, `HttpRequest`), Provider-backed Factory (`getInstance`), Direct Instantiation (baseline).
- *Structural* (11) — Decorator (I/O wrap / interceptor / HelloWorldWrap), Adapter / Bridge (NIO ↔ legacy, Reactive Streams ↔ Flow), Facade (`HelloWorldUtils`), Proxy (Mockito).
- *Behavioral* (17) — Strategy + Functional Interface (`HelloWorld`, `AsynchronousHelloWorld`), Template Method (`@implSpec` 외화), Observer (Publisher-Subscriber, 8 reactive 라이브러리), Async Callback (`CompletionHandler`), Future / Promise (`CompletionStage`), Command, Iterator (`BreakIterator`, `ServiceLoader`), Memento, State.
- *JDK Idioms* (11) — SPI (`ServiceLoader`), DI/IoC (Dagger / Guice / HK2 / Spring / OpenWebBeans / Weld / Micronaut / Avaje + CDI Producer-Disposer), Structured Concurrency (`StructuredTaskScope`), Mocked Construction, Marker annotation, Utility class, Producer-Consumer.

`HelloWorld` 인터페이스 한 점 (`set(byte[], int)`) 이 Strategy 의 변경 축, default 메서드 군이 Template Method 의 골격, `AsynchronousHelloWorld` 가 Strategy + Template Method 의 비동기 평행 트리, 그 위로 SPI / DI / Reactive / Async Callback / Structured Concurrency 가 같은 12 바이트 페이로드를 서로 다른 모양으로 흘려 보낸다 — 이 한 권의 책이 노리는 "JDK 의 I/O 관용구 전수 조사" 의 결과가 위 표 47 줄로 압축된다.
