== 개요

각 *테스트 메서드 하나하나의 본문 안에서* 발견되는 최적화 거리를 모은 보고서다. 모든 항목은
`ClassName.methodName()` 와 해당 본문의 라인 범위로 표시한다. "X개 파일이 Y 패턴" 같은
파일 단위 집계는 이 보고서의 형식이 아니다.

[NOTE]
====
이번 실행에서 대상 범위를 *메인 모듈 SUT* (예: `HelloWorld`, `AsynchronousHelloWorld`,
`ExecutorHelloWorld`, `StructuredConcurrencyHelloWorld`, `HelloWorld*Publisher` 등) 의 메서드를
검증하는 테스트로 한정했다. 일반 Java/JUnit/Mockito 데모, `_Effective_Java_*`,
`HelloWorldReactive_*`, `_Java_*`/`_Javax_*` 같은 라이브러리 탐색 테스트는 제외한다.
====

[NOTE]
====
`HelloWorld.java` 와 계약 테스트 `*_Test` 의 주석 처리된 줄들은 학습용 스캐폴드이므로 결함으로
보지 않는다. 주석 줄이 어떤 지역 변수를 참조하면 그 변수는 "orphan" 으로 간주하지 않는다.
====

* `ExecutorHelloWorld_*`, `StructuredConcurrencyHelloWorld_*`
* `HelloWorld_Byte_Publisher_Test`, `HelloWorld_Array_Publisher_Test`
* `HelloWorldImpl*` (lib 모듈)

범위 밖으로 분류된 대표 클래스:

* 일반 Java/JUnit/Mockito 데모: `ByteBufferTest`, `DataInputStream_Test`, `FileOutputStream_Test`, `Junit_Assertions_Test`, `Junit_Assumptions_Test`, `Mockito_Test`, `BDDMockito_Test`, `IntegralTest`, `FloatingPointTest`
* Effective Java 연습: `_Effective_Java_PECS_Test`
* 리액티브 라이브러리 탐색: `HelloWorldReactive_{Akka,Helidon,Jdk,Mutiny,Pekko,Reactor,RxJava3,Vertx}_Test`, `ReactiveHelloWorld_*`
* JCA / Crypto 탐색 (HelloWorld 메서드를 직접 시험하지 않는 것): `_Java_Security_*_Test`, `_Javax_Crypto_*_Test`
* 베이스 / 유틸리티: `HelloWorld__Test`, `HelloWorld__Publisher_Test`, `*TestUtils`, `*TestConstants`

== 점검한 메서드 패턴

* 같은 라인의 인접 중복 (`dup-line`)
* 선언 후 본문 어디에서도 읽히지 않는 지역 변수 (`orphan-local`)
* `ArgumentCaptor.forClass(...)` 선언 후 사용되지 않음 (`orphan-captor`)
* `mock(X.class)` 선언 후 사용되지 않음 (`orphan-mock`)
* `assertThrows(...)` 결과를 받은 변수에 `assertNotNull` 을 또 거는 경우 (`thrown-notnull`)
* verify-implies-consequence (`verify 가 이미 보장한 결과를 또 검증`)

== 발견

이번 실행에서는 *범위 안의 154 개 파일에서* 해당 패턴에 정확히 들어맞는 사례가 발견되지
않았다.

이전 실행에서 잡힌 6 건은 모두 범위 밖 파일 (`HelloWorldReactive_*`, `_Effective_Java_*`,
`ByteBufferTest`, `Junit_Assertions_Test`) 의 것이어서, 범위 축소 규칙에 따라 이 보고서에서는
제외했다.

[NOTE]
====
"발견 0건" 은 *현재 스캐너의 패턴* 에 정확히 들어맞는 것이 없다는 뜻이지, 범위 안 154
파일에 최적화 거리가 없다는 뜻은 아니다. verify-implies-consequence 같은 의미 단위 판단은
구문 일치만으로는 잡기 어렵고, 다음 실행에서 더 정밀한 규칙을 추가한다.
====

== 다음 실행에서 다룰 항목

1. verify-implies-consequence 패턴을 위한 더 정밀한 규칙 (`verify(coll).add(x)` → `coll.isEmpty()` / `coll.size()` 의 중복 단언, `verify(...).x(eq(v))` → captor 에서 또 `v` 단언 등)
2. cross-method 동일 본문 (`ClassName.methodA` 와 `ClassName.methodB` 가 `@DisplayName` 만 다르고 본문 동일)
3. 베이스 클래스가 이미 검증하는 invariant 의 서브클래스 재검증
4. 메서드 본문 안의 *의미 단위* 중복 — 같은 객체에 대한 동치 단언이 여러 줄에 흩어져 있는 경우 등
