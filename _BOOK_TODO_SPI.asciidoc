== What to cover (3 short parts)

=== 1. SPI interface visibility (`public`)

- Why the service interface must be `public` (loaded reflectively
  across module / class-loader boundaries by `ServiceLoader`;
  package-private types cannot be instantiated from outside their
  package).
- Show the actual `HelloWorldServiceProvider` declaration (read it
  fresh from disk — do NOT paraphrase) with `public interface ...` and
  explain that provider implementations must also have an accessible
  (`public`) zero-arg constructor *or* a `public static provider()`
  method.

=== 2. Classpath configuration — `META-INF/services/<FQCN>`

- A plain text file at
  `META-INF/services/com.github.jinahya.hello.lib.HelloWorldServiceProvider`
  whose lines are the fully qualified class names of providers.
- Works without any `module-info.java`; this is the original Java 6+
  mechanism.
- Show a 1–2 line example of the file content.
- Run command form: `java -cp ... MainClass`.

=== 3. Module-path configuration — `module-info.java`

- Consumer side:
  `uses com.github.jinahya.hello.lib.HelloWorldServiceProvider;`
  in the module that calls `ServiceLoader.load(...)`. Without it, the
  JVM throws:
+
[%unbreakable]
----
java.util.ServiceConfigurationError: ...
    module X does not declare `uses`
----
+
Mention this exact error so the reader can recognize it.
- Provider side:
  `provides com.github.jinahya.hello.lib.HelloWorldServiceProvider
   with com.github.jinahya.hello.lib.HelloWorldServiceProvider_Impl;`
  in the module that contains the implementation. When `provides` is
  declared in `module-info.java`, the `META-INF/services/...` file is
  not required.
- Run command form:
  `java --module-path ... --module <module>/<MainClass>`.

=== Closing paragraph

End with a one-paragraph note that the two mechanisms can coexist

that this project's lib-module tests rely on the classpath mechanism
at test time via surefire's `<useModulePath>false</useModulePath>` —
see `_ISSUES.asciidoc` for the rationale.
